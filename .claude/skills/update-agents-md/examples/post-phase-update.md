# Example: Update AGENTS.md after a phase retrospective

Most common use case. The retrospective surfaced new conventions, established a few rules the next phase needs to know, and possibly invalidated a few rules from earlier.

## Session start

```bash
git status
claude --model opusplan
```

## User opens with

> AGENTS.md needs updating after the phase-1 retrospective.

## Skill workflow

### 1. Read

Per SKILL.md "Read first":

- `AGENTS.md`
- `CLAUDE.md`
- `docs/plans/phase-1-retrospective.md`
- `pyproject.toml`
- `Makefile` if present
- `.claude/settings.json`
- `docs/adr/README.md`
- `src/lesson_graph/models.py` (only if the retrospective mentions schema invariants)

### 2. Confirm scope

> AGENTS.md is currently 92 lines. The phase-1 retrospective surfaces these candidate updates:
>
> Additions:
> - Package layout split (ADR 0006: `src/lesson_graph/` for schema, `src/lyw_core/` for everything else). Worth a hard rule because every phase-2 task will be tempted to put non-schema code under `lesson_graph/`.
> - Synthetic-PDF fixture pattern is the convention for phase-2 fixture work. Likely a one-liner.
> - Lazy-import convention for heavy ML deps (per phase-1 T10 finding). Probably belongs.
>
> Stale candidates:
> - Current "Tech (pinned)" section says `pip install -e '.[dev]'`. Replaced by `uv` in phase-0; the section was missed during T0a. Update.
> - "Working agreement" includes a rule about phase 1 being foundational. Phase 1 has shipped; rule is now stale and clutters the file.
>
> No removals proposed without your approval. Confirm scope: small additions plus stale-rule removals?

User confirms. Agent proceeds.

### 4. Reporting

After the diff:

> New line count: 95 (was 92). Net +3.
>
> Removals:
> - "Phase 1 is foundational. No phase-2 or phase-3 work begins until phase 1 ships..." — rule is stale; phase 1 has shipped.
>
> Additions:
> - Package layout hard rule (ADR 0006 reference) — the most common phase-2 mistake risk.
> - Synthetic-PDF fixture convention — phase-2 work will create new fixtures.
> - Lazy-import convention for heavy ML deps — phase-1 T10 finding, prevents test-collection slowdown.
>
> No additions push the file past 200 lines.
>
> One thing I considered but rejected: adding a rule about the `provenance` field on `ConceptNode`. The field is documented in `docs/02-data-model.md` and enforced by the schema; adding it to AGENTS.md would duplicate without adding constraint.

### 5. Closeout

User approves. Agent reminds:

> Saved. Verify by running a clean session: `claude --model sonnet`, then `/context`. Memory files should be under 5% of total context. If higher, the file needs more pruning.

## What good looks like

- Net change is small. AGENTS.md should grow slowly across phases.
- Every addition is a rule the agent would otherwise get wrong. No documentation for documentation's sake.
- Every removal is justified out loud. The user sees what was deleted and why.
- The reporting block flags rejections as well as inclusions — keeps the file from accreting.

## Common mistakes to avoid

- **Adding rules that duplicate hook enforcement.** If `.claude/settings.json` blocks the action, the AGENTS.md rule should reference the hook, not restate it.
- **Adding rules that duplicate the schema's docstrings.** If `models.py` already says "list-order means priority," AGENTS.md does not need to say it again.
- **Restating ADRs in full.** Reference the ADR by number; don't reproduce the rationale.
- **Padding rules to sound important.** "Critically, all developers MUST ensure..." is noise. "All DB access goes through repositories." is signal.
- **Adding praise, sentiment, or project-pitch language.** None belongs in AGENTS.md.
