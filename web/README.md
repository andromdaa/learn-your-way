# Learn Your Way — Web UI

The browser-facing pipeline UI for Learn Your Way OSS. A React 19 + Vite +
TypeScript single-page app that drives the FastAPI backend in
`src/lyw_core/` end-to-end: upload a source PDF, watch ingest jobs run,
explore the canonical lesson graph, generate personalized modalities, and
take quizzes.

In production this app is built to `web/dist/` and served by FastAPI as
static assets at `/`, with SPA fallback. In development it runs on its
own Vite dev server on port 5173 and proxies API calls to FastAPI on
port 8000.

> **Looking for the backend?** See the repository root
> [`README.md`](../README.md) and [`AGENTS.md`](../AGENTS.md). This file
> covers only the `web/` package.

## Stack

| Concern              | Choice                                      |
| -------------------- | ------------------------------------------- |
| Framework            | React 19                                    |
| Bundler / dev server | Vite 6                                      |
| Language             | TypeScript 5.8 (strict)                     |
| Routing              | TanStack Router (file-based, autosplit)     |
| Server state         | TanStack Query                              |
| Graph rendering      | Cytoscape.js + `react-cytoscapejs`          |
| Diagrams             | Mermaid                                     |
| Icons                | lucide-react                                |
| Tests                | Vitest + Testing Library + jsdom            |
| Lint                 | ESLint 9 (flat config) + typescript-eslint  |
| API types            | `openapi-typescript` against `/openapi.json`|
| Package manager      | pnpm                                        |

## Layout

```
web/
├── index.html              # Vite entry document
├── vite.config.ts          # dev proxy + Vitest config
├── eslint.config.js        # ESLint flat config
├── tsconfig*.json          # split TS configs (app / node / root)
├── public/                 # static assets copied verbatim
└── src/
    ├── main.tsx            # React/router bootstrap
    ├── index.css
    ├── routeTree.gen.ts    # generated by @tanstack/router-plugin
    ├── api/                # typed REST client, SSE helper, react-query hooks
    │   ├── client.ts
    │   ├── sse.ts
    │   └── hooks/
    ├── components/         # AssetViewer, ConceptGraph, MermaidAsset, …
    ├── routes/             # file-based routes (sources, lessons, quizzes, …)
    └── test-setup.ts       # Vitest global setup
```

`routeTree.gen.ts` is generated automatically by the TanStack Router
Vite plugin whenever a file under `src/routes/` is added or renamed —
do not hand-edit it.

## Prerequisites

You need these installed locally:

- **Node.js ≥ 20.19** (Vite 6 requirement; 22 LTS recommended)
- **pnpm ≥ 9** — install with `corepack enable && corepack prepare pnpm@latest --activate`, or via Homebrew / `npm i -g pnpm`
- A running backend if you want real data. The minimum is:
  - **Python 3.12 + uv** for the FastAPI app and Arq worker (see root [`AGENTS.md`](../AGENTS.md))
  - **Docker / Docker Compose** for Qdrant, Redis, and Ollama (see [`docker-compose.yml`](../docker-compose.yml))

Without a backend the UI loads, but every page that fetches data will
sit in a loading or error state.

## First-time setup

From the repository root (`learn-your-way/`):

```bash
# 1. Install web dependencies (uses pnpm-lock.yaml).
pnpm --dir web install

# 2. (Optional but recommended) bring up backend services.
docker compose up -d                # qdrant, redis, ollama, open-webui
uv sync --extra dev                 # install Python tooling once
uvicorn lyw_core.api.app:app --reload                   # FastAPI on :8000
arq lyw_core.worker.settings.WorkerSettings             # ingest worker
```

You can also run pnpm from inside `web/` directly (`cd web && pnpm install`)
— the `--dir web` flag is just a convenience so you don't have to leave
the repo root.

## Day-to-day development

```bash
# Start the Vite dev server (HMR, port 5173).
pnpm --dir web dev
```

Then open http://localhost:5173. The dev server proxies the following
paths to FastAPI on `http://localhost:8000` (see
[`vite.config.ts`](./vite.config.ts)):

- `/v1/*` — JSON API
- `/healthz`
- `/openapi.json`
- `/docs`, `/redoc`

That means the SPA always talks to *relative* URLs like `/v1/sources` —
in dev they hit Vite's proxy, in prod they hit FastAPI directly because
FastAPI serves `web/dist/` at the same origin.

### Available scripts

Defined in [`package.json`](./package.json):

| Script                  | What it does                                                       |
| ----------------------- | ------------------------------------------------------------------ |
| `pnpm dev`              | Vite dev server with HMR (port 5173)                               |
| `pnpm build`            | Production build to `web/dist/`                                    |
| `pnpm preview`          | Serve the production build locally (no proxy — needs FastAPI up)   |
| `pnpm lint`             | ESLint over the whole package                                      |
| `pnpm typecheck`        | `tsc --noEmit` against the project references                      |
| `pnpm test`             | Run the Vitest suite once (CI mode)                                |
| `pnpm codegen`          | Regenerate `src/api/types.ts` from FastAPI's `/openapi.json`        |

Run any of these from inside `web/` (`pnpm dev`) or from the repo root
(`pnpm --dir web dev`).

## Running against the real backend

The full stack the UI expects:

```bash
# Terminal 1 — infra
docker compose up -d

# Terminal 2 — pull the default instructional model once
docker compose exec ollama ollama pull gemma3

# Terminal 3 — FastAPI
uvicorn lyw_core.api.app:app --reload

# Terminal 4 — Arq ingest worker
arq lyw_core.worker.settings.WorkerSettings

# Terminal 5 — Vite
pnpm --dir web dev
```

Smoke-check that the proxy is wired up by hitting
http://localhost:5173/healthz — it should return the FastAPI health
payload.

## API typings (codegen)

The typed REST client in `src/api/client.ts` consumes types generated
from FastAPI's OpenAPI schema:

```bash
# FastAPI must be running on :8000 first.
pnpm --dir web codegen
```

This rewrites `src/api/types.ts`. Re-run it whenever the backend's
schema changes (new endpoint, changed payload, …) and commit the result
together with the backend change.

## Quality gates

Before opening a PR, run all four locally:

```bash
pnpm --dir web lint
pnpm --dir web typecheck
pnpm --dir web test
pnpm --dir web build
```

`build` is part of the gate because Vite's production build catches
real errors that `tsc --noEmit` does not (e.g. dynamic `import()`
failures, asset resolution).

Tests live next to the code they cover (e.g. `src/api/client.test.ts`)
and run under jsdom — see `src/test-setup.ts`.

## Production build

```bash
pnpm --dir web build
```

Outputs to `web/dist/`. FastAPI mounts this directory at `/` with SPA
fallback, so once it exists you can run only `uvicorn ...` and visit
http://localhost:8000 to use the same UI without a separate dev server.

To sanity-check the built bundle before deploying:

```bash
pnpm --dir web preview          # serves dist/ on http://localhost:4173
```

`preview` does **not** apply the dev proxy — start FastAPI on the same
host or expect API calls to fail.

## Configuration

The web app has no runtime environment variables of its own. Everything
it talks to is reached through same-origin relative paths, so there is
no `VITE_API_URL` to set. Backend behavior is configured on the Python
side via pydantic-settings (see root [`AGENTS.md`](../AGENTS.md)).

If you need the SPA to point at a non-default backend port during
development, edit the `server.proxy` block in
[`vite.config.ts`](./vite.config.ts).

## Troubleshooting

**`pnpm: command not found`** — enable Corepack
(`corepack enable && corepack prepare pnpm@latest --activate`) or install
pnpm globally.

**`EBADENGINE` / Node version errors** — upgrade to Node ≥ 20.19. `nvm
install 22 && nvm use 22` is the quickest fix.

**Blank page or 404s for `/v1/*` in dev** — FastAPI is not running on
port 8000. Start `uvicorn lyw_core.api.app:app --reload` and refresh.

**Type errors immediately after pulling** — the OpenAPI schema changed.
Run `pnpm --dir web codegen` (with FastAPI running) to refresh
`src/api/types.ts`.

**Changes under `src/routes/` aren't picked up** — `routeTree.gen.ts`
is regenerated by the Vite plugin on save. If it desyncs, restart
`pnpm dev`.

**Mermaid or Cytoscape renders blank** — both expect a sized container.
Check the parent element has non-zero width/height; that is by far the
most common cause.

**Ingest jobs never finish** — the Arq worker isn't running, or Ollama
hasn't pulled `gemma3` yet. Check `docker compose logs ollama` and the
worker terminal.
