# Phase 1 Retrospective

## What shipped

All eleven spec deliverables from `specs/phase-1-ingest.md` landed, and every task in the tracker is checked off (T0c through T15). The spec-coverage table maps each deliverable cleanly: the Docling parser (T5), heuristic and LLM-refined chunkers (T7, T9), round-trip span verifier (T6), inspection CLI (T13), hybrid BM25 + Qdrant + cross-encoder retrieval (T10–T12), SQLite schema and DAO (T4), filesystem adapter (T2), Docker Compose for Qdrant and Redis (T3), Ollama client (T8), Arq ingest worker (T14), and FastAPI endpoints (T15) all shipped. All acceptance criteria are now satisfied as of 2026-04-29: `tests/integration/test_parser_openstax.py` runs green against the committed fixture (7 heuristic-chunker concepts, span fidelity verified) and the inspection CLI output was reviewed and approved by the user. Phase 2 may open.

## Decisions that changed the spec

Several implementation choices made during phase 1 are load-bearing for phase 2. `ConceptNode.provenance` (ADR-0008, T7) is now the canonical attachment point for source fidelity; any phase-2 code that reads or writes concept metadata must go through that field, not invent a parallel channel. BM25 and Qdrant both index one document per `ConceptNode` — not per `SourceSpan` — using the first span as the provenance anchor; the retrieval interface in phase 2 inherits this granularity and cannot assume span-level hits. Asset paths use SHA-256 with a two-char prefix shard (ADR mirror of git object layout), and `doc_id` is consistently the full SHA-256 hex digest of the PDF bytes; the personalization layer must use the same convention when referencing sources. The SQLite schema stores concepts and source spans as relational rows with `ON DELETE CASCADE`, not JSON blobs, so any phase-2 DAO work should continue that pattern rather than reaching for blob serialization. Finally, `personalization_profile` in `models.py` is typed `dict[str, Any]` with an explicit `# TODO(phase-2)` to replace it with a `TypedDict` per `docs/02-data-model.md`; that replacement is a prerequisite before the personalization layer adds fields.

## What was harder than expected

Two tasks significantly overran. T5 (Docling parser) required a separate fix commit to resolve `mypy --strict` failures caused by `docling_core`'s lack of `__all__` on intermediate `__init__` modules — every import had to be rewritten to reference the canonical defining submodule directly, and `doc.num_pages()` had to be replaced with `len(doc.pages)` because the former is untyped. That mypy friction was preceded by the nix-vs-uv toolchain thrash: three agent-config commits between T4 and T5 (`d84b199`, `b8b03b8`, `019ba42`) burned session time resolving whether to use a Nix flake or uv before any task work could proceed. T14 (Arq worker) was the heaviest task by commit count, including a ruff N806 fix pass and a WIP stash, and surfaced a version conflict: arq 0.26+ requires `redis[hiredis]<6`, which collides with the project's `redis[hiredis]>=7.4.0` pin, forcing a downgrade to arq 0.25.0. T11 (Qdrant retrieval) hit a removed API — `QdrantClient.search` is gone in the 1.x line and required migration to `query_points` — and the 90% coverage gate forced adding a full mock-based unit test suite alongside the integration tests to compensate for model-download-gated integration paths.

## What was easier than expected

The constructor-injection seam pattern established in T8 (Ollama client) propagated cleanly through T11 and T12 without rework; by the time the cross-encoder reranker needed a test seam, the pattern was already in the codebase and no new ceremony was needed. T4 (SQLite DAO) and T8 both landed in a single commit each — the design decisions were clear enough upfront that no fix passes were needed. The TDD rhythm (failing tests → implementation → chore tick) held consistently across all fifteen tasks; the only deviation was T4 and T8 shipping implementation without a preceding failing-test commit, and neither caused a regression. The `pytest -m integration` placeholder established in T0c and the `asyncio_mode = "auto"` setting from T3 meant every subsequent async test just worked without per-test decoration. The 90% coverage gate was tighter than expected in a few spots but never required architectural changes — it was always addressable by adding unit tests with mocks, which is the right response.
